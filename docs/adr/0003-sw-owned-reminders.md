# Service worker owns reminders

Reminder checks moved from the page interval into the service worker: the app mirrors its state to IndexedDB via `sync-state` messages, and the SW computes due tasks itself (schedule, snooze, quiet hours, repeat interval). Triggers are page pings while the app is open, and Periodic Background Sync (`rutinko-reminders`, installed PWA on Chromium) while no tab is open. All reminders share one notification tag — multiple due tasks collapse into a single grouped notification instead of stacking. Notification actions taken while no window is open are applied to the SW state copy and queued in IndexedDB; the page drains the queue on next launch. Per ADR 0001 there is still no backend, so delivery with the browser fully closed remains best-effort (periodic sync on Android); guaranteed closed-browser delivery would require a Web Push server, which stays a separate decision.
