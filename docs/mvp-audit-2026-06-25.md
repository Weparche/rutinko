# Rutinko MVP boundary audit — 2026-06-25

This audit checks the current app implementation against the product boundaries captured in `CONTEXT.md` and ADRs.

## Patch status

Applied in `src/main.jsx` commit `1bd727d7abeef9756162387236e1e301b74aec0d`:

- First launch now starts with `tasks: []` instead of auto-created starter routines.
- Reset now clears local data and returns to an empty Today.
- Remaining English visible UI copy was replaced with Croatian copy.
- Main user-facing add/edit copy now says routine/rutina instead of generic task/zadatak where it affects product positioning.
- Reminder effect no longer recreates on every render.
- Notification copy now mentions the in-app skip path.

## Summary

Rutinko is now aligned with the MVP direction in the inspected React flow.

Previously identified issues were:

1. **Empty Today Start** was not respected for first-time users because the app auto-created starter routines.
2. **Croatian-only MVP** was not fully respected because a few user-facing strings were still in English.

Those issues have been patched.

The current implementation is broadly aligned with the MVP decisions: PWA-first, free, no login, no sync, no export/backup, no calendar view, no strict mode, neutral skip, fixed categories, routine templates, paused routines and one-time routines.

## Applied blocking fixes

### 1. First launch is now truly empty

Previous behavior:
- When no state existed, `getInitialState()` created tasks from `ROUTINES.slice(0, 10).map(createTask)`.
- When stored data was malformed or missing `tasks`, the parser fallback also created starter tasks.
- `resetApp()` restored those same starter tasks.

Current behavior:
- First launch creates an empty `tasks: []` state.
- Malformed stored state falls back to `tasks: []`.
- Reset clears local data and returns to an empty Today, not starter routines.
- Routine templates remain visible as explicit quick-add suggestions, but nothing is added until the user taps Add.

### 2. Remaining English UI copy was replaced

Previous English-facing copy:
- “Daily autopilot” in the header.
- “Daily flow” in the Today hero.
- “Rutinko builder” in the add screen.
- “Done” in task quick actions.

Current Croatian replacements:
- “Dnevni autopilot”
- “Dnevni tok”
- “Dodavanje rutine”
- “Završeno”

### 3. User-facing terminology is now more routine-oriented

Updated examples:
- “Novi zadatak” → “Nova rutina”
- “Zadatak dodan.” → “Rutina dodana.”
- “Spremi zadatak” → “Spremi rutinu”
- “Uredi zadatak” → “Uredi rutinu”
- “Izbriši zadatak” → “Izbriši rutinu”

## Applied technical polish

### 4. Reminder interval effect stabilized

The reminder `useEffect` now has a dependency array instead of re-creating the interval on every render.

### 5. Notification text mentions all in-app resolution paths

Previous notification body:
- “Stisni Završeno ili odgodi podsjetnik.”

Current notification body:
- “Označi kao završeno, odgodi ili preskoči u aplikaciji.”

Reason:
- The previous body hid the neutral Skip path, which is an explicit MVP decision.

## Aligned areas — no change needed

### PWA-first MVP

The app has PWA install logic and service worker notification handling. This aligns with PWA-first and does not imply a native app.

### Free MVP

No subscription, paywall, ad or in-app purchase implementation was found in the inspected React flow.

### Local-only MVP

The app stores data in browser `localStorage`. No login, OAuth, backend sync, cloud sync, export or backup flow was found in the inspected React flow.

### No Calendar MVP

No calendar view, date picker, month view, agenda or future planning screen was found in the inspected React flow.

### Routine templates

The built-in `ROUTINES` list works as a quick-add catalog. This is correct as long as templates are not auto-added on first launch.

### Paused routines

The implementation supports `active === false`, hides paused routines from Today and keeps them editable in My Routines. This aligns with the glossary.

### One-time routines

The utility logic shows `once` routines only on the creation day. This aligns with the one-time routine decision.

### Neutral skip

Skip resolves the task for today without negative scoring or punishment. This aligns with the neutral Skip decision.
