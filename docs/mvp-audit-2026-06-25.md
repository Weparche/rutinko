# Rutinko MVP boundary audit — 2026-06-25

This audit checks the current app implementation against the product boundaries captured in `CONTEXT.md` and ADRs.

## Summary

Rutinko is mostly aligned with the MVP direction, but the current app still violates two important decisions:

1. **Empty Today Start** is not respected for first-time users because the app still auto-creates starter routines.
2. **Croatian-only MVP** is not fully respected because a few user-facing strings are still in English.

The rest of the current implementation is broadly aligned with the MVP decisions: PWA-first, free, no login, no sync, no export/backup, no calendar view, no strict mode, neutral skip, fixed categories, routine templates, paused routines and one-time routines.

## Blocking fixes before final MVP polish

### 1. Make first launch truly empty

Current behavior:
- When no state exists, `getInitialState()` creates tasks from `ROUTINES.slice(0, 10).map(createTask)`.
- When stored data is malformed or missing `tasks`, the parser fallback also creates starter tasks.
- `resetApp()` restores those same starter tasks.

Required behavior:
- First launch should create an empty `tasks: []` state.
- Malformed stored state should fall back to `tasks: []`.
- Reset should clear local data and return to an empty Today, not recreate starter routines.
- Routine templates remain visible as explicit quick-add suggestions, but nothing is added until the user taps Add.

Recommended code changes:
- In `getInitialState()`, replace all automatic `ROUTINES.slice(0, 10).map(createTask)` fallbacks with `[]`.
- In `resetApp()`, set `tasks: []`.
- Rename reset copy from “Vrati početne zadatke” to “Obriši lokalne podatke”.
- Update confirmation copy to “Obrisati lokalne podatke i vratiti prazan Danas?”

### 2. Remove remaining English UI copy

Current English-facing copy found:
- “Daily autopilot” in the header.
- “Daily flow” in the Today hero.
- “Rutinko builder” in the add screen.
- “Done” in task quick actions.

Required behavior:
- All visible copy in MVP should be Croatian-only.

Recommended replacements:
- “Daily autopilot” → “Dnevni autopilot”
- “Daily flow” → “Dnevni tok” or “Danas”
- “Rutinko builder” → “Dodavanje rutine”
- “Done” → “Završeno”

### 3. Align user-facing terminology around routines

Current behavior:
- Add/edit flows still use “zadatak” in many places: “Novi zadatak”, “Zadatak dodan”, “Spremi zadatak”, “Izbriši zadatak”.

Decision context:
- Internally a `Task` is a daily routine occurrence.
- User-facing product should feel like a routine autopilot, not a generic todo app.

Recommended replacements:
- “Novi zadatak” → “Nova rutina”
- “Zadatak dodan.” → “Rutina dodana.”
- “Spremi zadatak” → “Spremi rutinu”
- “Uredi zadatak” → “Uredi rutinu”
- “Izbriši zadatak” → “Izbriši rutinu”

## Non-blocking technical polish

### 4. Stabilize reminder interval effect

Current behavior:
- The reminder `useEffect` has no dependency array, so it re-creates the interval on every render.

Recommended behavior:
- Keep reminder behavior the same, but add a dependency array that reflects the values used by the reminder check.
- This is not a product boundary violation, but it is worth fixing before final polish.

### 5. Notification text should mention all in-app resolution paths

Current notification body:
- “Stisni Završeno ili odgodi podsjetnik.”

Recommended copy:
- “Označi kao završeno, odgodi ili preskoči u aplikaciji.”

Reason:
- The current body hides the neutral Skip path, which is an explicit MVP decision.

## Aligned areas — no change needed

### PWA-first MVP

The app has PWA install logic and service worker notification handling. This aligns with PWA-first and does not imply a native app.

### Free MVP

No subscription, paywall, ad or in-app purchase implementation was found in the inspected React flow.

### Local-only MVP

The app stores data in browser `localStorage`. No login, OAuth, backend sync, cloud sync, export or backup flow was found in the inspected React flow.

### No Calendar MVP

No calendar view, date picker, month view, agenda or future planning screen was found in the inspected React flow.

### Routine templates

The built-in `ROUTINES` list works as a quick-add catalog. This is correct as long as templates are not auto-added on first launch.

### Paused routines

The implementation supports `active === false`, hides paused routines from Today and keeps them editable in My Routines. This aligns with the glossary.

### One-time routines

The utility logic shows `once` routines only on the creation day. This aligns with the one-time routine decision.

### Neutral skip

Skip resolves the task for today without negative scoring or punishment. This aligns with the neutral Skip decision.

## Recommended implementation order

1. Patch `src/main.jsx` for empty first launch and reset behavior.
2. Patch visible English copy.
3. Rename user-facing “zadatak” copy to “rutina”.
4. Patch reminder effect and notification copy.
5. Run build/deploy.
